영차영차 등반대 — 코스 1: 첫 발이 길을 연다

목표: 발판을 먼저 움직이면 상단 손 홀드가 닿는다는 발견.
시점: 정면 곰돌이. 손발 4개 중 하나 선택 후 드래그. 기존 IK/도달 판정 유지.

원점: 왼쪽 상단 (0,0), W=700 / H=1550, y 아래로 증가.
이미지에 표기된 홀드 위치는 아래 JSON과 동일.

시작: 왼손 S1 / 오른손 S2 / 왼발 F1 / 오른발 F2.
F1/F2는 시작 발판, F3/F4는 첫 이동용 발판.
F5/F6는 중간 발판, U1/U2는 중단의 안정적인 저그.
F7/F8은 다음 구간 발판. R은 오른쪽 위험 크림프(꿀).
G는 최종 목표 저그.

배치 의도
- 시작 상태에서 U1/U2/G/R로 직접 손을 옮길 수 없음.
- 첫 이동은 왼발 F3 또는 오른발 F4 등 발판 선택 유도.
- 중앙 U1/U2 경로는 안전, R은 추가 보상으로 우회.
- 코스 1이라 실제 미끄러짐이나 스태미나 소모로 즉시 낙하하는 추가 규칙은 넣지 않음.

기존 reach-core 솔버 재검증 (해당 코드에서 제공하는 판정 기반)
- 최단 일반 완등: 6수
  왼발 F3 → 오른발 F5 → 왼손 U1 → 왼발 S1 → 오른발 S1 → 오른손 G
- 꿀 수집 + 완등: 7수
  왼손 S2 → 왼발 F3 → 오른발 F5 → 왼발 S1 → 오른손 R → 오른발 S1 → 왼손 G

주의: 기존 코드의 canPlace()는 같은 타입(손끼리/발끼리) 홀드 중복이나
발이 손용 저그를 디디는 것을 엄격히 막지 않으므로 위 경로는 아직
'보기 좋은 등반 자세'나 '동일 홀드 중복 금지'까지 검증한 것은 아님.
JSON만 갈아끼운 뒤 design-tool/bear-test에서 실제 연결 자세와 코스 품질을 검수해야 함.
특히 일반 경로의 동일 S1 두 발과 꿀 경로의 S2 손 중복은 교정 대상.
게임 규칙을 무단 변경하지 않고 설계와 검수 사항으로 남겨둠.

적용 순서
1. 현재 파일 백업/원본 보존.
2. reach-core.js의 const STAGE=...; 데이터 블록만 course1-stage.js 내용으로 교체.
3. 기존 스테이지/엔진 파일의 다른 영역은 변경하지 않기.
4. 정면 캐릭터 테스트와 손발 접점 확인 후 피드백에 따라 홀드 좌표 조정.

동일 홀드에 다른 손발이 동시에 붙는 것을 금지하는 강화 검사도 시행함:
- 일반 완등 7수: 왼발 F3 → 오른발 F5 → 왼손 U1 → 오른손 U2 → 왼발 S1 → 오른발 S2 → 왼손 G
- 꿀 수집 7수: 왼발 F3 → 오른발 F5 → 왼손 U1 → 왼발 S1 → 오른손 R → 오른발 S2 → 왼손 G
이는 임시 강화 검사에서의 결과이며, 기존 canPlace()를 아직 변경하지 않았음.

최종 채택 기준
- 초반 발판 우선 행동을 플레이어 스스로 발견하는지
- 안전 경로와 위험 경로 중 선택 이유가 명확한지
- 억지로 손발이 교차하거나 홀드를 겹쳐 쓰는 해법이 없는지
- 1회 완등 후 다시 해보고 싶은지
